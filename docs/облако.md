# Синхронизация: телефон и ноутбук на одних данных

Приложение — статический сайт: своего сервера у него нет и не будет. Поэтому
хранилище и вход берём готовые. Выбран **Supabase**: там есть и база, и вход
через Google, и обращаться к ним можно обычными запросами — без чужих
библиотек, которых в проекте нет нигде.

Данные лежат одной строкой на человека: всё состояние целиком, как оно есть на
устройстве. Это не лень — так устроено слияние: две копии сводит `sync.js` на
самом устройстве, и базе не нужно ничего про них знать. Захочется когда-нибудь
разложить по таблицам — данные к этому готовы, но нужды в этом нет.

**Облако — копия, а не хозяин.** Планер работает без сети и без входа. Войти
можно в любой момент, и то, что уже записано на устройстве, при входе не
заменяется облачным, а сливается с ним.

## Что сделать один раз

**1. Завести проект.** На supabase.com → New project. Регион — поближе.

**2. Создать таблицу.** В проекте → SQL Editor → выполнить:

```sql
create table public.states (
  user_id    uuid primary key references auth.users on delete cascade,
  data       jsonb not null,
  changed_at text  not null default '',
  updated_at timestamptz not null default now()
);

alter table public.states enable row level security;

-- Свою строку видит и правит только её хозяин. Это и есть защита данных:
-- открытый ключ приложения сам по себе не даёт доступа ни к чему.
create policy "своя строка" on public.states
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);

-- Пишем всегда одну и ту же строку, поэтому «кто» проставляется сам:
-- приложению незачем знать свой идентификатор, чтобы не ошибиться в нём.
alter table public.states alter column user_id set default auth.uid();
```

**3. Включить вход через Google.** В проекте → Authentication → Providers →
Google. Там же написано, какой адрес вставить в Google Cloud Console как
разрешённый (`https://<проект>.supabase.co/auth/v1/callback`), и куда положить
Client ID и Client Secret оттуда.

В Google Cloud Console: APIs & Services → Credentials → Create credentials →
OAuth client ID → Web application. В «Authorized redirect URIs» — адрес из
Supabase.

**4. Разрешить возврат в приложение.** Supabase → Authentication → URL
Configuration → Redirect URLs: `https://lirav.github.io/Life-os/`

**5. Вписать два значения** в `app/js/cloud-config.js`:

```js
export const CLOUD = {
  url: 'https://<проект>.supabase.co',
  key: '<ключ anon>',
};
```

Оба открытые: их видно любому, кто откроет исходники сайта, и это нормально.
Данные закрывает не ключ, а правило из пункта 2.

## Что происходит дальше

Настройки → «Войти через Google». После возврата приложение забирает то, что
в облаке, сливает с тем, что на устройстве, и отправляет общее обратно. Дальше
свои правки уходят сами через несколько секунд после изменения, а чужие
забираются при запуске и при возвращении на вкладку.

«Выйти» разрывает связь с облаком и **не трогает записи на устройстве**.

## Что стоит знать

- Если одну и ту же запись править на двух устройствах, пока они не сошлись,
  победит более поздняя правка целиком. Разные записи, разные дни, разные
  сферы сливаются без потерь.
- Нет сети — планер работает как работал: облако догонит.
- Копия в файл никуда не делась и остаётся самым надёжным запасным путём.
