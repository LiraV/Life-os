# Синхронизация: телефон и ноутбук на одних данных

Приложение — статический сайт: своего сервера у него нет и не будет. Поэтому
хранилище и вход берём в **Yandex Cloud**, где уже есть учётка.

Устройство складывается так:

- **Вход** — Яндекс ID. Браузер получает токен и посылает его с каждым запросом.
- **Функция** (Cloud Functions) — единственная, кто решает, чьи это данные:
  она спрашивает у Яндекса, чей токен, и открывает файл только того человека.
- **Хранилище** (Object Storage) — один файл `state/<id>.json` на человека:
  всё состояние целиком, как оно есть на устройстве.

Одним файлом — не от лени: две копии сводит `sync.js` на самом устройстве, и
хранилищу незачем знать про их устройство. Захочется когда-нибудь разложить по
таблицам — данные к этому готовы, но нужды в этом нет.

**Облако — копия, а не хозяин.** Планер работает без сети и без входа. Войти
можно в любой момент, и то, что уже записано на устройстве, при входе не
заменяется облачным, а сливается с ним.

## Что сделать один раз

### 1. Приложение в Яндекс ID

[oauth.yandex.ru/client/new](https://oauth.yandex.ru/client/new) → веб-сервис.

- **Redirect URI:** `https://lirav.github.io/Life-os/`
- **Доступы:** «Доступ к адресу электронной почты» и «Доступ к логину». Больше
  ничего не нужно — приложению нужно только знать, кто вошёл.

Сохрани **ClientID** — он понадобится в конце.

### 2. Бакет

Yandex Cloud → Object Storage → создать бакет. Доступ — **закрытый**: наружу
он не смотрит, ходить в него будет только функция.

### 3. Сервисный аккаунт и ключ

Yandex Cloud → Сервисные аккаунты → создать, роль **storage.editor**.
Затем у этого аккаунта → «Создать новый ключ» → **статический ключ доступа**.
Запиши идентификатор и секрет: секрет показывается один раз.

Он живёт только в настройках функции и в браузер не попадает никогда.

### 4. Функция

Yandex Cloud → Cloud Functions → создать → версия:

- Среда: **nodejs18** (или новее)
- Способ: **редактор кода**, файл `index.js` — вставить `server/yandex/index.js`
  из этого репозитория. Зависимостей нет, `package.json` не нужен.
- Точка входа: `index.handler`
- Таймаут: 10 секунд, память: 128 МБ
- Сервисный аккаунт: тот, что из пункта 3
- Переменные окружения:
  - `BUCKET` — имя бакета
  - `KEY_ID` — идентификатор статического ключа
  - `SECRET` — секрет статического ключа
  - `ORIGIN` — `https://lirav.github.io`

### 5. Шлюз

Yandex Cloud → API Gateway → создать. Спецификация:

```yaml
openapi: 3.0.0
info: { title: life-os, version: 1.0.0 }
paths:
  /state:
    x-yc-apigateway-any-method:
      x-yc-apigateway-integration:
        type: cloud_functions
        function_id: <ID функции>
        service_account_id: <ID сервисного аккаунта>
```

Адрес шлюза вида `https://<id>.apigw.yandexcloud.net` — он и есть адрес облака.

### 6. Вписать два значения

`app/js/cloud-config.js`:

```js
export const CLOUD = {
  api: 'https://<id>.apigw.yandexcloud.net',
  clientId: '<ClientID из пункта 1>',
};
```

Оба открытые: их видно любому, кто откроет исходники сайта, и это нормально.
Данные закрывает не они, а функция: она спрашивает у Яндекса, чей токен, и
чужой файл не отдаст.

## Что происходит дальше

Настройки → «Войти через Яндекс». После возврата приложение забирает то, что
в облаке, сливает с тем, что на устройстве, и отправляет общее обратно. Дальше
свои правки уходят сами через несколько секунд после изменения, а чужие
забираются при запуске и при возвращении на вкладку.

«Выйти» разрывает связь с облаком и **не трогает записи на устройстве**.

## Что стоит знать

- Если одну и ту же запись править на двух устройствах, пока они не сошлись,
  победит более поздняя правка целиком. Разные записи, разные дни, разные
  сферы сливаются без потерь.
- Нет сети — планер работает как работал: облако догонит.
- Функция не принимает пустое состояние: это почти всегда сбой на стороне
  устройства, а записать пустоту поверх целого — потерять всё разом.
- Копия в файл никуда не делась и остаётся самым надёжным запасным путём.

## Сколько это стоит

Один человек, десяток синхронизаций в день, файл в сотню килобайт. Вызовы
функции и запросы к хранилищу в таком количестве попадают в бесплатный объём;
за хранение выходят копейки в месяц. Шлюз и функция сами по себе, без вызовов,
денег не стоят.
