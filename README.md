# Жизнь в одном месте

Личная операционная система: цели года → квартала → месяца → недели → дня, мягкая RPG-геймификация,
кривая энергии под хронотип и Летописец, который подсказывает по твоим же отметкам.
Без стриков и чувства вины: пропуск ничего не отнимает, прогресс только копится.

**Приложение:** https://lirav.github.io/Life-os/
**Дизайн-пакет (прототип, вайрфреймы, хендофф):** https://lirav.github.io/Life-os/design/

## Что умеет

| Экран | Что делает по-настоящему |
| --- | --- |
| **Онбординг** | Собирает персонажа: имя, хронотип, норма сна, интроверсия, активность, стартовые привычки, тема года. |
| **День** | Квест можно привязать к занятию с полки: отметил его выполненным — занятие само засчитано в полке, трекере и статистике сферы, отмечать дважды не нужно. Ритм дня: привычки с нормой и плюсом в один тап. Любая дата в обе стороны. Кривая энергии строится из хронотипа, ползунок пишется в момент касания и хранится по дням; рядом волна за 30 дней. Пока день не отмечен, видно, что это подсказка по хронотипу, а не твоя отметка. Квесты: создание, время, длительность, сфера, связь с целью, метка «босс», перенос на другой день, удаление. После спорт-квеста всплывает рефлексия и пишется в дневник. |
| **Сроки на «Дне»** | Задания учёбы со сроком показываются на своём дне отдельным блоком: отметить можно прямо оттуда, задание уходит в «сдано» на своей доске. Сама запись остаётся там, где заведена — второй копии не появляется. Просроченное показывается на сегодня, иначе оно пропадает из виду совсем. **Рабочих задач тут нет намеренно**: личный день не должен превращаться в рабочий список. |
| **Доска работы** | Процесс ведения рекламных кампаний перенесён из отдельного канбана целиком: девятнадцать колонок в трёх зонах — сверху РК и архив, ниже расчёт МП, внизу прочие задачи. Карточка знает всё, что знала там: тип (МП / РК / прочее), колонку, площадки, месяц РК, дедлайн, код запроса, бюджет, сплит, ссылки, срочность и чек-лист. При переходе в новую колонку **чек-лист этапа добавляется сам**, без дублей — сверка идёт по тексту пункта. Есть «отчёты по неделям» на месяц карточки, «дубликат» для сплитов по гео и креативам и «копия на следующий месяц» для многомесячных РК: она начинает путь заново с проверки заявки, а дедлайн и день работы у неё сбрасываются. Фильтры: поиск, тип, площадка, месяц, только срочные. Доску можно перенести из выгрузки старого канбана — уже перенесённое не двоится, сверка по названию и колонке. |
| **День работы** | У карточки две даты, и они разные. **Дедлайн** — срок сдачи: он только подсвечивается на карточке (просрочен, сегодня, ближайшие три дня) и никуда больше не идёт. **«Когда делаю»** — день, в который задача попадёт в «На сегодня» на экране «Работа»; до него она лежит в свёрнутом «Дальше». Закрытые колонки не считаются ни там, ни там. Единственный след за пределами сферы — тихий счётчик у пункта «Работа» в ящике «Ещё»: он виден, только когда открываешь меню. На «Дне» рабочих задач нет намеренно. |
| **Ноутбук** | Доска — единственный экран, которому тесно в телефонной рамке, поэтому на широком экране приложение раскрывается во всю ширину: зоны показывают заголовки групп, фильтры становятся полосой, карточки перетаскиваются мышью между колонками. На телефоне те же колонки листаются вбок, фильтры прячутся в шторку, а перенос делается кнопкой «перенести» со списком колонок. Раскрытие включается только на доске — на остальных экранах рамка возвращается. |
| **Инбокс** | Место, куда мысль кладут, не решая сразу, когда её делать: одна строка и Enter — ни даты, ни сферы вводить не нужно. Отсюда ничего не уходит само. «В сегодня» — один тап, потому что это самый частый случай; «перенести» открывает четыре направления: в день на выбранную дату, в цель месяца, квартала или года, этапом в сферу, повторяющимся делом в «Заботу». После переноса запись уходит из инбокса — она уже там, где ей место. Убрать без переноса тоже можно. У каждой записи видно, сколько она лежит, — не для укора, а чтобы было понятно, что пора решить; пустой инбокс так и говорит «просто пусто», без задачи разобрать его. На «Дне» есть «+ в инбокс» и строка со счётчиком, которая появляется, только когда там что-то есть. |
| **Планы** | Реальные ISO-недели, месяцы и годы. Босс недели с этапами. Намерения на год, квартал и месяц — список направлений («ходить в зал», «отдыхать»), который не отмечают и не считают. Динамичные цели месяца — «сходить на вокал 3/5», набираются одним тапом и живут только внутри месяца. Цели трёх горизонтов — год, квартал, месяц: добавление, правка, этапы, архив, смена горизонта. Цель можно отметить выполненной целиком, одной галочкой, без дробления на этапы, вести счётчиком («7 из 12 книг», «30 000 из 150 000 ₽») или вычеркнуть — пометка «в этом году не закрою», при которой цель остаётся и в списке, и в расчётах. Цель года может стоять без срока, а потом её кладут в любой квартал или месяц — это та же цель, а не копия. Цель месяца может вести к цели квартала, та — к цели года, и прогресс поднимается по цепочке: из этапов → в цель → в квартал → в год. |
| **Работа** | Сфера про наём. **Мест работы может быть несколько**, и у каждого свой график, оклад, норма офиса и отпуск — со вторым наймом общими они быть перестают. При этом второй наём не утяжеляет экран тому, у кого он один: пока место одно, выбора места нет нигде, он появляется сам. Из графика места считается норма дня и недели, поэтому отметить день это один тап («Отработала · в офисе»), а не анкета. День бывает четырёх видов — работала, выходной, отпуск, больничный — и отмечается отдельно по каждому месту: отпуск на одной работе и рабочий день на другой выражаются как есть. Экран считает **нагрузку и границы, а не производительность**: часы недели против суммарной нормы, переработку сверх графика, серию дней подряд без выходного (по всем местам сразу), дни в офисе против нормы каждого места, отпуск. «Мало сделала» не считается нигде. Часы складываются, а дни — нет: два места в один день это всё равно один рабочий день. Доска — канбан из четырёх стадий: очередь → в работе → на проверке → готово; «на проверке» нужна отдельно, потому что сделанное и ждущее ответа — разные состояния. Задача принадлежит месту и, необязательно, проекту; проект тоже принадлежит месту. «Опыт и победы» — отдельная лента: не задачи, а то, чему научилась. Стоимость часа считается **по каждому месту отдельно** — оклад делённый на его же часы; ставки разных работодателей не складываются, среднее было бы красивым враньём, а вот оклады складываются, и это показано. |
| **Путь** | Места работы во времени, вертикальной шкалой: период, длительность, вид найма, текущее выделено. Параллельные места нормальны и показаны как есть, а общий стаж считается календарно — два найма разом не дают двойного стажа. Перерыв показывается, только если в это время не было **вообще никакой** работы: пока хоть одно место ещё длилось, перерыва не было. Месяцы считаются как в резюме, обе границы включительно: «июнь — декабрь» это семь месяцев, а месяц, в котором работа закончилась, в перерыв не идёт. Убранное место уносит свои отметки дней, но задачи и опыт остаются. |
| **Свои сферы** | Набор сфер перестал быть константой: встроенные лежат в коде, свои — в состоянии, и маршрут `#/spheres/<ключ>` рисует их тем же экраном. Создание идёт от заготовки — «Практика», «Полка», «Коллекция», «Доска», «Список дел», «Дневник числа», «С нуля». Заготовка только заполняет форму — пока не нажмёшь «Создать», ничего не появляется, и всё можно переписать до и после. У своей сферы есть имя, эмодзи вместо иллюстрации (изображение не храним — экспорт должен остаться лёгким), подпись на плитке и механики. Ключ — uid, а не имя, поэтому переименование не рвёт ссылки из квестов и целей. Своя сфера сразу встаёт в общий строй: попадает в выбор сферы у квеста и цели, даёт строку в трекере года и цель «отсюда» с автосчётом. Убрать её можно, удалить — нет: она уходит из списка, а этапы, журнал и связанные цели остаются в данных. |
| **Механики сферы** | Шесть кирпичей, из которых собирается своя сфера; можно взять несколько сразу — у каждой механики свой ящик в данных, поэтому они не мешают друг другу. **Этапы** — список с галочками и прогрессом. **Журнал** — отметки по дням: неделя тапами как в «Ритме», повторный тап снимает, «вписать за день» ставит своё число за любую дату, ноль убирает. **Полка** — «хочу → в процессе → сделано → отложено», дата окончания проставляется сама, отложенное остаётся статусом, а не провалом. **Коллекция** — единицы с датой: видно и «за год», и «за всё время»; дату можно поставить прошлую, если это было давно. **Доска** — «не начато → в работе → готово», тап по стадии двигает дальше, с последней возвращает в начало, дата перехода запоминается. **Замеры** — число с датой, разница с прошлым разом и лучшее; лучшее считается только если сказано, куда «лучше», иначе так и написано. Каждая считающая механика даёт свою строку в трекере года и свой источник для цели «отсюда»; у замеров источника нет — «сколько раз я мерил» не цель. |
| **Убрать с глаз** | Любую сферу — встроенную или свою — можно скрыть с плиток. Данные остаются нетронутыми, а скрытые собраны отдельным блоком внизу и возвращаются одним тапом. Это нужно ровно затем, зачем свои сферы: приложение про всю жизнь не должно расти в ширину бесконечно. |
| **Роли** | Ролей восемь: Учёная, Читательница, Атлет, Целительница, Артистка, Мастерица, Хранительница, Странница (с мужскими формами из общего словаря). Набор фиксирован — это характеры, а не пользовательские папки. А вот какая сфера к какой роли относится — данные: раскладка переехала из кода в состояние и правится в самой сфере. Поэтому «Работа» перестала быть сиротой, «Страны» получили роль, а своя сфера встаёт в круг наравне со встроенными, не требуя правки ролей. Считает роль по-прежнему только то, у чего есть дата: у поездки её нет, поэтому «Странница» живёт квестами. |
| **Цели из сферы** | У «Библиотеки», «Стран», «Спорта», «Обучения» и «Бюджета» есть кнопка «+ Цель отсюда»: сфера показывает, что умеет считать, человек ставит число и срок. Набранное такая цель не хранит — считает: прочитанные книги и страницы, страны за год и за жизнь, тренировки и тренировки с конкретной пилюлей, занятия с полки, остаток копилки. Поэтому у неё нет кнопок «+1» — вписывать число руками значило бы завести второе про то же самое, и в «Планах» под ней написано, откуда оно берётся. Срок ограничен тем, что данные позволяют посчитать: у поездки есть только год, поэтому месяц и квартал там не предлагаются. Готовых целей нет ни одной — пока не нажмёшь «Добавить», в планах ничего не появляется; повторная такая же цель за тот же период не заводится. |
| **Спорт** | Шаблоны тренировок и упражнения с рекордами. У тренировки есть пилюли — «пресс», «руки», «зал с тренером»; их можно вешать несколько сразу и заводить новые прямо в шторке. Пилюлю можно переименовать или убрать тапом по ней в карточке «Пилюли» — история при переименовании не рвётся. Именно пилюли считаются в трекере года: программа со временем меняется, а «пресс» остаётся прессом, поэтому статистика не рвётся при смене тренировки. Шаблон отдаёт свои пилюли новой тренировке. В самой сфере дат нет: там лежат шаблоны — название и набор упражнений с подходами. Тренировка появляется на конкретном дне через «+ тренировка» на экране «День»: можно подтянуть шаблон и получить готовый состав, а можно собрать с нуля. Строка дня остаётся строкой: состав раскрывается тапом по тренировке, и там у каждого упражнения своя галочка. Тап по упражнению меняет подходы и повторы — сколько угодно раз после ввода. В шаблоне набор правится так же: тап по строке. В рекорды идёт только отмеченное — и тренировка, и само упражнение: запланированное, но не сделанное, результатом не считается. Отметка всей тренировки закрывает состав целиком, но ручную разметку по упражнениям не затирает. Как у квеста, у тренировки видно сферу и цель, к которой она относится, — но цели двигаются только вручную, автоматики закрытия нет. У упражнения своя единица и направление роста: больше лучше, меньше лучше или важны оба; максимум и минимум показываются всегда, направление решает лишь, что считать рекордом. Рекорд, последний результат и сдвиг за месяц — на карточке упражнения; в трекер года идут не упражнения, а пилюли. Замер можно записать и без тренировки — он не попадает в статистику как тренировка. |
| **Учёба** | Заведение → предмет → этапы. Диплом здесь не особая сущность, а предмет с длинной цепочкой этапов. Этап живёт на доске-канбане и двигается по стадиям от «не начато» до «сдано»; стадия «у преподавателя» считает дни ожидания. Вкладка «Сейчас» показывает просроченное, что ждёт ответа, ближайшие сроки и что в работе. Этап одним тапом становится целью месяца. |
| **Обучение** | Полка занятий вместо общего списка этапов. Курс делится на модули, а внутри модуля — уроки: галочка модуля закрывает и открывает все его уроки разом, модуль без уроков считается одной ступенью. Прогресс курса считается по конечным точкам, а не по числу модулей и процентом, практика — ритмом: сколько занятий в месяце и когда было последнее. Отметка занятия ставится задним числом, заметка уходит в дневник. Пауза — нейтральное действие. Галочка «считать и в спорте» добавляет занятие в статистику спорта и в потребность «Движение». Практики сами становятся строками годового трекера. |
| **Бюджет** | Планировщик по образцу личной таблицы: план на месяц по статьям расходов и доходов, факт по неделям, копилки отдельно от трат, правила трат. Единственный источник правды — список операций: остаток и балансы копилок считаются из него и переходят из месяца в месяц. Выгрузка и загрузка .xlsx: выгруженный файл и есть формат загрузки, повторный импорт не плодит дубли. Понимает и покупной планировщик — забирает из него план месяца по статьям. | Под заголовком видно, когда бюджет заполняли в последний раз: отметку двигает любая правка данных — операция, план статьи, копилка, правило, импорт, — но не листание месяцев и вкладок.
| **Питание** | Календарь месяца: заливка дня по близости к норме калорий. На каждый день — КБЖУ, вода с быстрым добавлением, список приёмов пищи. Оценка приёма через OpenAI — по фотографии или по описанию словами («тарелка борща и два куска хлеба»). Снимок уходит в модель и нигде не сохраняется; в дневник ложатся только числа, которые можно поправить перед сохранением. |
| **Библиотека** | Полка книг: «хочу прочитать» → «читаю» → «прочитано», плюс «отложено» — отдельный статус, а не удаление. У книги автор, вид (бумажная, электронная, аудио), объём и закладка «докуда дочитала»: прогресс и остаток считаются сами, если объём известен. Даты начала и конца проставляются при смене статуса. Во вкладке «Год» — что дочитано по месяцам, сколько страниц и средняя оценка (книги без оценки в среднее не идут). В трекер года добавляется строка «Книги», когда за год закрыта хотя бы одна. |
| **Страны** | Где была за жизнь и что из этого случилось в конкретный год. Поиск по русским названиям — хватает трёх букв, флаг собирается из кода страны, поэтому в состоянии лежат два символа, а не картинка. Одна поездка — одна отметка с годом и заметкой: в одну страну можно съездить трижды, а «за жизнь» она всё равно считается один раз. Отмеченное группируется по частям света, рядом счёт «N из 197». |
| **Сферы** | Девять сфер со своими механиками: этапы с прогрессом, у блога — стадии идей (росток → бутон → готов → публикация), у бюджета — копилка с пополнением, у спорта — статы из выполненных квестов. |
| **Ритм** | Привычки без стриков, с дневной нормой и шагом: «таблетки 0/3», «вода 0/2000 мл» по 250 за тап. Норма не ограничена сверху. Недельная сетка по реальным датам, месячные итоги, добавление и удаление. Норма дня отмечается прямо на главном экране. |
| **Одна вода** | Привычку про воду можно связать с «Питанием» — галочкой в самой привычке. Тогда числа не синхронизируются: его просто одно. Норма берётся из норм питания, стакан, отмеченный в «Ритме», сразу виден в «Питании» и наоборот, а в трекер и выгрузку вода попадает через ту же связь. У тех, у кого привычка про воду уже была, связь включается при обновлении; прошлые значения переезжают в «Питание» один раз и только если они и правда в миллилитрах и день там пуст — иначе день, у которого воду обнулили руками, воскресал бы при каждой загрузке. Свой журнал привычки при этом не стирается и возвращается, если связь снять. |
| **Форма** | Вкладка в «Теле», где тело, еда и спорт лежат на одном отрезке — 30 или 90 дней. Из замеров берётся разница веса и мерок между первым и последним замером периода, из питания — среднее КБЖУ и вода, из спорта — число отмеченных тренировок и по каким пилюлям. Среднее по еде считается только по заполненным дням, и прямо сказано, сколько их было: пустые дни занижали бы картину. Выводов о причинах экран не делает и говорит об этом прямо — это три ряда рядом, а не причина и следствие. Оттуда же связка в «Питание»: норму белка можно поставить от последнего веса (1,2–1,6 г на кг) одной кнопкой, без автоматики. |
| **Тело** | Календарь месячных: тап по любому дню, включая прошлые; отметка периода диапазоном дат; правка и удаление цикла. Из отметок считаются день цикла, фаза, средняя длина цикла и месячных, прогноз следующих. Симптомы с выбором даты, замеры с историей и дельтами. Раздел цикла показывается по отдельному тумблеру в профиле: выключенный прячет его с экрана, но не трогает ни одной отметки. Рядом карточка «Сложение» — ИМТ, талия относительно порога, тип кости и суточный расход; всё это ориентиры, и рядом сказано, чем каждый из них не является. |
| **Профиль тела** | В «Я» рядом с именем: пол, дата рождения, рост, обхват запястья. От пола зависят обращение и те нормы, которые в методиках действительно разные: формула расхода калорий (Миффлин — Сан Жеор, −161 у женщин и +5 у мужчин), порог талии по ВОЗ (80/88 см против 94/102) и пороги индекса Соловьёва для типа сложения (15/17 против 18/20). ИМТ от пола не зависит — это сама методика, а не упущение. Считается только то, для чего есть данные: без роста нет ИМТ, без даты рождения нет расхода. В «Питании» норму калорий можно поставить расчётом одной кнопкой — дефицит или профицит от неё остаётся решением человека. |
| **Род обращения** | Приложение написано в женском роде — это его родной голос, поэтому женская форма везде идёт первой, а мужская подставляется. Меняются названия ролей, титулы уровня, имена черт и те строки, которые говорят про человека: «докуда дочитала», «уже сделала», «когда сделала». Голос самого приложения при этом не меняется: «Записала», «Убрала» — это оно о себе, а не о тебе. Формы лежат словарём в одном месте: правила для русского рода нет, и выводить его алгоритмом было бы враньём. Летописцу пол сообщается в той же выжимке, что показана под полем ввода. |
| **Расписание** | Необязательная вещь: у занятия с полки, предмета учёбы и шаблона тренировки можно задать дни недели, время, длительность и место — а можно не задавать, и тогда ничего не меняется. Хранится правило, а не события по датам: расписание можно поправить задним числом, и прошлое не поедет. Есть чередование «раз в две недели» от указанного дня, срок «с и по» и пауза. Одно занятие можно перенести на другой день или отменить, не трогая правило: «итальянский по четвергам» остаётся по четвергам, даже если конкретное занятие уехало на пятницу. На своём дне при этом остаётся строка «перенесено на 26 августа» или «отменено на этот раз» с кнопкой «вернуть» — чтобы отмена не пропадала бесследно. Событие показывается на «Дне» строкой рядом с квестами, а отметка идёт в ту же запись, что и обычно: занятие засчитывается в полке и трекере, посещение предмета — в учёбе, а тренировка по расписанию превращается в настоящую тренировку дня с составом из шаблона и после этого из расписания пропадает, чтобы не задваиваться. |
| **Забота** | Повторяющиеся дела, которые держат в порядке тело, внешность, дом и питомца: анализы и врачи, маникюр и эпиляция, ТО и страховка, вакцины и глисты. У дела своя периодичность, и «когда пора» считается от последней отметки, а не от календаря: сделала раньше или позже — план поехал за тобой. Пока дело ни разу не отмечено, показывается плановый месяц, а не выдуманный день. Три вида: «Сейчас» — что пора и что скоро, «Списком» — по группам, «Год» — двенадцать месяцев как в бумажной заметке, только пересчитываются сами. Замеры тела не дублируются: их отметка берётся из «Тела». У питомца свой профиль — кличка, возраст из даты рождения, вес с разницей от прошлого раза и свои дела. |
| **Список заботы** | Готового списка больше нет: раньше каждому доставался один и тот же личный набор на 31 дело вместе с чужой кличкой питомца. Теперь «Забота» предлагает — по полу, возрасту и наличию питомца, — а человек отмечает, что берёт. Женщине предлагается гинеколог, мужчине уролог; маммография появляется после сорока, ПСА после сорока пяти, колоноскопия после сорока пяти; дела питомца — только когда питомец заведён. Пока не заполнена дата рождения, возрастные дела просто не всплывают. Часть предложений отмечена заранее — это предложение, а не выбор за человека: снять можно любое, и пустой выбор шторка примет молча. Уже заведённое не предлагается второй раз, даже если оно добавлено руками. В шторке прямо сказано, что это не назначения: периодичность различается по странам, по врачам и по человеку. У тех, кто пользовался прежней версией, список остаётся как был. |
| **Липкая шапка** | При прокрутке верх экрана остаётся на месте: заголовок, вкладки и стрелки дат должны быть под рукой, а не уезжать вверх. Собирается в одном месте — в роутере, а не в девятнадцати экранах: экраны начинаются с одних и тех же элементов (заголовок, подзаголовок, вкладки, строка со стрелками), и их достаточно завернуть в один липкий блок. Несколько липких соседей налезали бы друг на друга — поэтому именно обёртка. Высокая шапка съедала бы экран, поэтому она обрезается до трети высоты: лишнее сверху возвращается в поток, ведь вкладки и фильтры полезнее заголовка. Треть — это примерно два ряда пилюль; на доске работы их три, и заголовок с кнопкой «назад» честнее отпустить, чем держать полэкрана занятым. Фон появляется только когда под шапку что-то уехало — на нетронутом экране сплошная заливка читалась бы как приклеенная панель. Подсказка экрана в шапку не попадает: она читается один раз и должна прокручиваться. |
| **Подсказки** | Необязательные. После онбординга приходит предложение показывать их — можно отказаться, и второй раз не спросят. Если согласиться, на каждом экране один раз появляется карточка на три строки: что здесь делать и чего можно не бояться. Она не блокирует экран — им можно пользоваться, не закрывая подсказку. «Понятно» гасит карточку этого экрана, «не показывать» — все сразу. Включить заново и обнулить показанные можно в настройках. |
| **Аватар** | Пятьдесят портретов или первая буква имени, как было. Выбор живёт в «изменить» и всплывает отдельным окном — тап по кружку в профиле открывает то же самое. Выбранное видно и в профиле, и в ящике «Ещё». В состоянии хранится только короткий ключ вроде `a12`, а не изображение, — экспорт остаётся лёгким. Картинки лежат в `assets/avatars`; первый десяток попадает в офлайн-кэш при установке, остальные кэшируются, когда открываешь выбор. |
| **Осознанность** | Вкладка во «Внутри»: семь практик без аудио и без обещаний. Четыре дыхательных — коробочное 4-4-4-4, 4-7-8, физиологический вздох, удлинённый выдох — идут с кругом, который дышит вместе с тобой: длительность перехода ставится на смене фазы, поэтому анимация идёт средствами CSS, а не кадр за кадром, и уважает `prefers-reduced-motion`. Ещё есть тишина (просто таймер, без указаний), сканирование тела по шагам и заземление 5-4-3-2-1 в своём темпе, без таймера. У каждой техники указан источник, и там же сказано, чего у неё нет: у 4-7-8 честно написано, что строгих клинических доказательств немного. Перед практикой можно отметить, насколько напряжена сейчас, после — как стало; **обе отметки необязательны**, и если «до» не поставлена, «после» не спрашивается — сравнивать было бы не с чем. Приложение показывает среднее твоих же отметок и прямо говорит, что это не эффект практики. Закончить можно в любой момент: записывается то, что успела, а не заявленное. Дни с практикой идут строкой в трекер года, и на них можно поставить цель. Стриков нет и здесь. |
| **Внутри** | С Летописцем можно разговаривать: нить помнит себя, поэтому это беседа, а не набор разовых вопросов. Экран открывается снизу — сразу видно поле ввода и последние сообщения, как в любой переписке. Он не сыплет советами сразу — сначала уточняет, что ты имеешь в виду; без чувства вины и без бодрого коучинга. Не врач: диагнозов не ставит и при серьёзном честно говорит, что нужен живой человек. В OpenAI уходят твои сообщения, нить и выжимка — квесты, энергия, цели, привычки, потребности, просроченная забота; дневник только по галочке, цикл, КБЖУ и бюджет не отправляются никогда, и это написано прямо под полем ввода. Без ключа OpenAI остаются офлайн-ответы на правилах. Рядом — шесть тестов: свой опросник мотивации и пять шкал по опубликованным методикам (TIPI, Grit-S, rMEQ, регуляторный фокус, SCS-SF). У каждой указан источник, обратные пункты считаются как положено, результат разбирается по шкалам, и прямо в нём сказано, что это самоотчёт, а не диагностика. Результаты работают: rMEQ обновляет хронотип, экстраверсия из TIPI — ползунок интроверсии, часть шкал даёт черты; где методика не ложится в одну черту, черта не выдумывается. И дневник. |
| **Я** | Полка из двадцати одной черты: полученные и ещё закрытые, с подсказками, как их заработать. Титул уровня, потребности за 7 дней, круг ролей за 14, жемчужина дня, энергия за 90 дней со связками по фазам цикла и занятиям. |
| **Трекер года** | Таблица по месяцам: строки — привычки, динамичные цели и свои строки. У привычек считаются только дни, когда норма закрыта целиком. Заливка ячейки по величине; значение за месяц можно вписать руками поверх расчёта — такие ячейки помечены точкой, ежедневные отметки при этом не меняются. Свою строку можно слить с занятием, привычкой или упражнением из спорта: месячные значения переезжают в её ручные правки, дубль исчезает. Совпадение названий приложение замечает само и предлагает объединить. Итог за год с лучшим месяцем и подпись, когда данные трогали в последний раз. Выгрузка и загрузка .xlsx: свод по месяцам, лист с дневными отметками; при загрузке пустые клетки и совпавшие с расчётом значения не превращаются в ручные правки. |
| **Настройки** | Профиль, экспорт и импорт JSON, полный сброс, подсказка по установке на телефон. |

## Данные

Всё живёт **только на твоём устройстве** — в `localStorage` браузера. Ни сервера, ни аккаунта,
ни аналитики: ничего не уходит наружу. Отсюда два следствия:

- Данные привязаны к конкретному браузеру. На другом устройстве будет пусто.
- Если очистить данные сайта, всё пропадёт. Поэтому в настройках есть **«Скачать копию (JSON)»** —
  этим же файлом данные переносятся на другое устройство через «Загрузить из копии».

Летописец — это правила поверх твоих отметок, а не языковая модель: он работает офлайн,
ничего не отправляет и никогда не меняет цели сам, только предлагает.

## Установить на телефон

Открыть https://lirav.github.io/Life-os/ и добавить на домашний экран:
на iPhone — «Поделиться» → «На экран „Домой“», на Android — меню браузера → «Установить приложение».
Дальше открывается без браузера и работает офлайн.

## Как устроено

Ванильный JavaScript с ES-модулями, без сборки и зависимостей: что лежит в репозитории,
то и отдаётся браузеру. Поэтому GitHub Pages публикует его как есть, без CI.

Цели — один список с горизонтом (`year` / `quarter` / `month`), периодом (`2026`,
`2026-Q3`, `2026-08`) и необязательной ссылкой `parentId` на цель покрупнее.
Поле `slots` — периоды помельче, в которые цель положена: она остаётся одним
объектом с общими этапами и прогрессом, просто показывается ещё и там.
Намерения лежат отдельно от целей, в `intentions` по ключу периода: у них нет
ни прогресса, ни отметок — это принципиально не задачи.

Черты (`app/js/traits.js`) — не подписи, а правила. У каждой есть декларативный
эффект, который читают экраны и Летописец: как показывать прогресс, каким тоном
говорить, какой отдых предлагать, когда ставить тяжёлое. Часть выдают тесты,
часть пересчитывается из ползунков профиля, часть персонаж зарабатывает сам —
проверки по фактам сводятся при каждой отрисовке и назад не отбираются.

Прогресс считается рекурсивно: отметка `done` перебивает всё, дальше счётчик
(`current` из `target`), этапы, вложенные цели, ручное значение. Флаг `dropped` —
только пометка «в этом году не закрою»: цель зачёркнута визуально, но остаётся
во всех расчётах и списках. Убирает цель с глаз лишь архив.

Состояние меняется только через `update()` из `store.js`: он мутирует объект, сохраняет
с задержкой и перерисовывает активный экран. Экраны — чистые функции `render()` плюс
таблица `actions`, куда роутер раздаёт клики по `data-act`.

## Локально

```bash
python3 -m http.server 8000   # затем http://127.0.0.1:8000/
```

Через `file://` не заработает: ES-модули и сервис-воркер требуют http.

## Обновление на устройствах

Код приложения сервис-воркер берёт **из сети в первую очередь**, а кеш держит
только как запас для офлайна; из кеша сразу отдаются лишь картинки и шрифты,
которые не меняются. Поэтому после выкладки устройство подхватывает новую
версию на первом же запуске, а не «когда-нибудь».

Номер сборки лежит в `app/js/version.js` и виден в настройках приложения —
по нему сразу понятно, старый код на устройстве или новый. **Поднимайте
`BUILD` при каждой выкладке**, иначе диагностировать будет нечем. В `sw.js`
есть свой `VERSION` для имени кеша: его тоже стоит поднять, когда меняется
список `SHELL`.

Если устройство всё же залипло на старой версии, в настройках есть
«Обновить приложение»: снимает регистрацию воркера, чистит кеши и
перезапускается. Данные лежат в `localStorage` и от этого не страдают.
